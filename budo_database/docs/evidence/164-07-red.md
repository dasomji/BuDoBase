## Authoritative contract

The focused suite follows #158's hardened export boundary:

- existing centralized staff + view + export authorization and Turnus scope
  remain before filter parsing/query construction;
- first issuance captures the selected Turnus maximum event ID, uses explicit
  zero for an empty Turnus, applies `id <= snapshot_id`, and excludes its own
  `audit.export` row plus rows appended before lazy stream consumption;
- issuance writes one exact metadata-only `audit.export` row before returning a
  stream; any validation/database/runtime insertion exception returns a
  sanitized 503 with no stream or event payload;
- the generic `audit.export` validator requires the exact result/filter keys,
  integer types, nonnegative signed-bigint result count, filter count no greater
  than the eight supported filters, successful outcome, and outer
  `audit_log/<turnus-id>` envelope;
- the first NDJSON line is exact schema v2 with sensitive classification,
  full-authorized payload policy, selected Turnus, and snapshot ID;
- event records retain their complete existing envelopes and full details,
  including the reconstructable `kid.edit` object;
- no temporary/staging file API is used;
- 200/403/404/503 responses carry exact private/no-store privacy headers, with
  NDJSON content type and attachment disposition on success.

The legacy export header assertion was advanced from v1 to the same v2 shape so
the eventual implementation has one compatible contract.
