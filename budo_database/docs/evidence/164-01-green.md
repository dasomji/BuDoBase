Date: 2026-07-31

Implemented only the dedicated schema validator and the minimal existing audit
service dispatch required for successful `kid.edit` events. No producer,
reader, migration, or UI was added.

## Production behavior

- `budo_app.kid_edit_audit.validate_kid_edit_details()` validates the exact
  `budo.kid-edit` v1 top-level, snapshot, 27-field, period, focus, event, and
  target key sets.
- It enforces storage-faithful scalar types and bounds, strict dates, positive
  non-boolean IDs and versions, unassigned/assigned version consistency,
  ordered unique dynamic collections, equal before/after configuration sets,
  and exact canonical changed paths.
- Successful validation reconstructs fresh plain `dict` and `list` JSON values
  in deterministic schema order.
- `MAX_KID_EDIT_AUDIT_BYTES` is exactly 4 MiB. Validation measures compact,
  sorted-key, non-ASCII-escaped UTF-8 JSON before schema traversal; exactly
  4 MiB is accepted and one byte more is rejected.
- `budo_app.audit` dispatches `kid.edit` details to this validator only when
  the outer envelope is `success`, resource type `child`, and a canonical
  positive decimal child ID.
- The generic action schema, sensitive-key set, 4 KiB byte limit, 500-character
  string limit, list/depth controls, and normal validation path are unchanged.
