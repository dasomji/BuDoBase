## Authoritative policy contract

The #158 policy is the exact intersection of authenticated, active, staff, and
`budo_app.view_auditevent`; export additionally requires
`budo_app.export_auditevent`. Permissions never grant a nonstaff account access,
and `is_superuser=True, is_staff=False` remains denied.

`budo_app/audit_tests/test_audit_policy.py` specifies:

- the compact full actor matrix through public `can_view_audit` and
  `can_export_audit` helpers;
- fixed-metadata denial logging containing only actor ID, endpoint kind, and a
  fixed reason code;
- representative nonstaff-with-permissions and staff-without-view list/export
  requests return 403 before filter parsing, query construction, serialization,
  or export building;
- bootstrap keeps its existing `permissions` object and keys but exposes the
  centralized effective booleans, without denial logs or a new capability object;
- ordinary authorized staff receive 404 for explicit foreign/nonexistent Turnus,
  while a staff superuser may explicitly select another Turnus;
- no active Turnus and no explicit authorized superuser selection returns an
  empty scoped result without constructing an unscoped audit queryset.

Old audit HTTP expectations were updated only where the new contract changes
staff setup, denial from 200 payload to 403, or foreign scope from empty 200 to
404.
