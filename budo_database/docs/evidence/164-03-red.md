# #164-03 RED — non-sensitive kid-edit audit payload preflight

Date: 2026-07-31

Scope: management-command tests and evidence only. No command implementation,
producer, reader, migration, staging, commit, push, or external `docs/` artifact

## Authoritative contract

GitHub issue #164 and its linked implementation specification require the
preflight to construct the exact snapshot for every child in the candidate
Turnus, print only sizes/counts/offending structural paths, never values, and
exit nonzero for unsupported candidate-Turnus data. The specified command name
is `check_kid_edit_audit_payloads`.

## Bounded RED coverage

`budo_app/audit_tests/test_kid_edit_audit_preflight_command.py` contains four
command-level tests:

- optional `--turnus-id` checks only that candidate; omission checks all children;
- every child is passed to the intended serializer with explicit, realized
  active periods, focus links, events, and assignments rather than lazy querysets;
- output is limited to aggregate checked/supported/unsupported counts, total and
  maximum encoded byte sizes, the 4 MiB limit, and safe child IDs/structural paths;
- a candidate Turnus with zero children succeeds with zero aggregates;
- an over-contract string and representative unsupported scalar type exit
  nonzero with only `child_id` plus `fields.<field>` path;
- an otherwise-valid payload over the exact 4 MiB UTF-8 limit exits nonzero with
  child ID, root path, encoded size, and limit;
- synthetic child names, field values, and oversized payload content never
  appear in stdout or stderr.
